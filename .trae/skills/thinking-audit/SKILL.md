# thinking-audit：思维链冗余审计

对一份已导出的 AI 思维链文本（.txt / .md）做定量测量与冗余模式识别，输出带行号证据的审计结论。只读分析：不改被审计文件、不改代码、不当场改规则。

## 1. 适用与不适用

适用：
- 用户上传 / 粘贴思维链导出文件，要求分析「有没有问题 / 是否过长 / 是否冗余 / 该怎么优化」
- 用户提供多份思维链，要求对比走势

不适用：
- 审查代码 / 变更质量 → `review-change`
- 排查功能故障本身 → `diagnose-issue`（本技能审的是「思考过程」，不是「功能」）
- 要求当场改变 AI 的思考行为 → 本技能只审计已发生的思考；行为约束走规则
- 行为复盘 / 评分沉淀 → `agent-retro`

与 `agent-retro` 的分界：用户要**行为复盘 / 评分沉淀**（主观评价，需认可结论 + 评分 + 复盘备注）→ `agent-retro`（仅手动触发）；只提供思维链文件要**冗余测量**（客观定量审计）→ 本技能。用户说「复盘一下这次思考」时按其目的判别，不确定就问一句。

## 2. 核心原则

1. **长度不是罪名**。判定看冗余率与信息密度，不看总字符。任务类型（诊断 / 实施 / 生成）与任务规模（文件数、需求数、产出复杂度）是长度合理性的分母；同类比较才有意义。
2. **每个结论带行号**。冗余指控必须引用行号区间；无行号证据不写。
3. **新证据测试（最重要的判别）**。区分两种循环：
   - **空转循环**：同一问题重推，各轮无新事实输入 → 冗余
   - **收敛循环**：每轮带来新输入（读到新代码、算出新数值、发现新约束）→ 有效推理，绕多轮也不算冗余
   - 判据：把该循环各轮的新增输入列出来；某轮列不出新输入，该轮即空转
4. **动作相关性测试（与新证据测试并列的第一判别）**。对每段推演问一句：**「这个答案会改变下一步动作吗？」** 不会 → 冗余，**无论它是第几次出现**。新证据测试只能抓「重复出现」的空转；抓不住「只出现一次但从头就不该想」的过度展开。典型：对用户已声明的事实（「我撤回了提交」）考古其发生机制——无论考古出哪种机制，下一步动作完全相同，整段推演零价值。任务规模越小，此测试越要先跑。
5. **最短充分路径是长度分母**。先列出完成该任务的必要动作（查什么、问什么、做什么）并估算预算字符，再与实际总字符对比得**膨胀倍数**。模式重复率只衡量「链内重复」；单次出现的不必要推演只有靠膨胀倍数才能定罪。
6. **不只挑毛病**。必须同时核查有效产出（捕获的 bug、算术、关键决策），否则分不清「长而有值」与「长而空转」。
7. **审计者不当场立规则**。同一模式跨 ≥2 条链复现才建议加规则；单链出现一律「观察，暂不动」。

## 3. 流程

### 3.1 全量读取

分块读完整份文件，记录：
- 链条类型：诊断 / 实施规划 / 生成（影响模式权重与基线）
- 任务规模：改动文件数、需求数、产出物复杂度

### 3.2 定量统计

```powershell
$f = "<思维链文件路径>"
$content = [System.IO.File]::ReadAllText($f)
$lines = [System.IO.File]::ReadAllLines($f)
$hmm  = ([regex]::Matches($content, '(?i)\bhmm\b')).Count
$wait = ([regex]::Matches($content, '(?i)\bwait\b')).Count
[pscustomobject]@{
  chars   = $content.Length
  lines   = $lines.Count
  hmm     = $hmm
  wait    = $wait
  density = [Math]::Round(($hmm + $wait) / $content.Length * 10000, 1)   # 每万字符次数
}
```

hmm / wait 是自我推翻频率的代理信号，**判据用密度口径**（代码块已一并计算）：`(hmm + wait) ÷ 总字符 × 10000`。**> 20 / 万字符**为空转信号，**< 5 / 万字符**基本健康。绝对次数（>100 / <30）只对 5 万字符以上的特大链作辅助备注，不作主判据——长度归一化前，5k 字符的链 100 次和 50k 字符的链 100 次完全不可比。只作信号，不作定罪证据。

### 3.3 分段切分与测量

按**逻辑转折**切段（不是均匀切），典型段：问题接收 → 假设生成 → 机制深挖 → 方案对比 → 实施规划 → 收尾自查。

```powershell
function Seg($from, $to) { ($lines[($from-1)..($to-1)] -join "`n").Length }
Seg 10 40   # 第 10–40 行的字符数
```

疑似重复的两段（两份草稿 / 两份计划）分别测量并**量化重复率**确认：

```powershell
$d1 = ($lines[120..174] -join "`n"); $d2 = ($lines[407..464] -join "`n")
$l1 = $d1 -split "`n"; $l2 = $d2 -split "`n"
$same  = (Compare-Object $l1 $l2 -IncludeEqual -ExcludeDifferent).Count   # 两段都出现的行数
$same / [Math]::Max($l1.Count, $l2.Count)   # 重复率 = 相同行数 ÷ 较长段行数
```

**重复率 ≥ 0.70 记高重复**，报告直接写百分比数值（如「重复率 82%」），不写「差异行数少 = 高度重复」这类目测结论。

各段字符合计应 ≈ 总字符（行换行统计口径差，小偏差忽略）。

### 3.4 冗余模式识别

对照 §4 模式目录逐条过，每个命中记：模式名 + 行号区间 + 估算字符。**先跑动作相关性测试（§2 第 4 条）再查模式目录**——模式目录只抓「重复出现」，抓不住单次出现的过度展开。

### 3.5 有效性核查（结论的另一半）

- 数真实产出：捕获的 bug 数、关键决策数
- 抽查链内算术与可验证技术论断（用自身知识复核；复核不了的标注「未验证」，不下结论）
- 记录**内容盲区**：链条全程未考虑的维度（交互行为、边界条件等）——属「遗漏」不属「冗余」，单独列出，不计入冗余率

### 3.6 最短充分路径预算（判定前必做）

列出完成该任务的必要动作清单并逐项估算字符预算（例：读指令 + 查状态 ≈400、发现矛盾问一句 ≈150、结论 ≈200），合计得**充分预算**。然后：

```
膨胀倍数 = 实际总字符 ÷ 充分预算
```

预算估算允许 ±50% 误差；倍数对误差不敏感（21x 不会因估算误差跌到 5x 以下）。诊断类 / 生成类任务的必要动作更多，预算相应放大后再比。

**中段敏感警告**：倍数落在 **2–5x 区间**时，判定对预算估计敏感——预算估 2000 还是 3000 可直接翻转「轻微 / 中度」。此时报告必须列出对倍数影响最大的 1–2 个预算项及其依据（如「查状态 ≈400 的依据是 N 次调用」）供用户仲裁；必要时给乐观 / 悲观两个预算夹逼，两档不一致时取轻档。

### 3.7 判定与输出

双口径同时报，**取更重的一档为最终判定**：

**口径一：链内重复率** = 冗余字符合计 ÷ 总字符

| 重复率 | 判定 |
|---|---|
| < 10% | 健康 |
| 10–25% | 轻微 |
| 25–50% | 中度 |
| > 50% | 严重 |

**口径二：路径膨胀倍数** = 实际总字符 ÷ 最短充分路径预算

| 膨胀倍数 | 判定 |
|---|---|
| < 2x | 健康 |
| 2–5x | 轻微 |
| 5–10x | 中度 |
| > 10x | 严重 |

两口径冲突时以膨胀倍数为准（重复率抓不住单次出现的过度展开；一条命令级任务写 1.6 万字符，即使零重复也是严重冗余）。两口径都健康才判健康。

## 4. 冗余模式目录

条款来源：`.trae/rules/02-redlines.md`（CodeBuddy / WorkBuddy 侧同一套在 `.codebuddy/rules/02-redlines/RULE.mdc`）。**按条款名引用，不按编号**——编号重排不断链；跨仓复用时按条款名重新映射。本仓库 `02-redlines` 没有独立的「思考收敛」条款族，下表第四列已重新映射到现有条款名（禁止思考 / 出处纪律 / 意图先复述 / 最小范围 / 排查铁律·单矛盾单取证 / 是非提问只回答有无）。

| # | 模式 | 检测特征 | 防误伤判别 | 对应规则条款 |
|---|---|---|---|---|
| 1 | 无证据循环 | 同一假设反复展开推演，结论未变 | 新证据测试：列各轮新增输入；有新输入算收敛 | 禁止思考（无新事实不重推） |
| 2 | 重读循环 | 用户原话被重新解读 ≥3 次 | 初读 + 歧义确认 1 次属正常 | 意图先复述（一次复述即锚点） |
| 3 | 记忆摇摆 | 外部事实（文档/规范/registry）反复估测置信度，不查证 | 查证一次后带防护定论属合规 | 出处纪律（外部事实靠出处，不靠记忆） |
| 4 | 验证前展开 | 主假设无证据时已写文件清单/代码草稿/验证步骤 | 方向已获用户确认后展开实施属合法 | 意图先复述（未确认不出实施清单） |
| 5 | 双草稿 | 同一文件完整草拟 ≥2 次，diff 仅注释/风格差异 | 「骨架→决策收敛→展开」的单草稿流程合规 | 未覆盖（观察项） |
| 6 | 决策无锚点重议 | 前文已得出的决策，后文从头再议一遍 | 结论有明确锚点可引用的复用不算 | 禁止思考（部分覆盖） |
| 7 | 计划多遍 | 文件改动清单列 ≥3 次 | 为精确 Edit 匹配而引用现状代码属必要 | 未覆盖（观察项） |
| 8 | 死路设计 | 先设计多级降级/兜底链，后发现权限/配置一行修复即可 | 查过一行修复不存在后再设计降级属合规 | 排查铁律·单矛盾单取证 |
| 9 | 声明未执行 | 「先查一下 X」声明后未执行，后文再声明一遍 | 链末声明留待执行阶段属正常 | 未覆盖（观察项） |
| 10 | 无关漫游 | 超出最小范围的顺带分析 | 「报告但不顺手修」的克制属合规 | 最小范围 |
| 11 | 决策无关推理 | 推演某问题的答案，但无论答案是什么、下一步动作都相同（含：对用户已声明的事实考古其发生机制，如「撤回是 hard 还是 soft reset」） | 动作相关性测试：答案会分叉后续动作才算必要推理 | 禁止思考（部分覆盖） |
| 12 | 计划书代替执行 | 可一条命令查证的状态（ls / status / reflog），不跑命令，先在链内写数百字符的验证计划或逐轮脑内枚举可能性 | 链末声明留待执行阶段属正常（模式 9）；此处指「明明可查却用推演替代查证」 | 是非提问只回答有无（精神延伸） |

模式 11 / 12 的特征是**单次出现即定罪**（动作相关性测试），不依赖重复次数——这是它们与模式 1–10 的本质区别。

「未覆盖（观察项）」处理：单链出现只观察并记录；跨 ≥2 条链复现才建议补规则条款，防规则膨胀。

## 5. 输出格式

固定七块，紧凑呈现（表格为主，报告语言跟随用户）：

1. **链条画像**：类型 / 总字符 / 行数 / 自我修正标记数 / 分段表（段名 + 行区间 + 字符）
2. **最短充分路径**：必要动作清单 + 预算字符 + 膨胀倍数
3. **冗余清单**：模式 + 行号区间 + 估算字符 + 合计（模式 11/12 命中时明确标注「单次即定罪」）
4. **双口径分档**：链内重复率 + 路径膨胀倍数，取更重档
5. **有效产出**：bug 捕获、复核过的算术/论断、内容盲区（单列）
6. **判定**：健康 / 轻微 / 中度 / 严重 + 一句证据
7. **建议**：只给两类——映射到已有规则条款，或「跨链复现后立新规则」；单链倾向「暂不动」

多链趋势（用户提供多份时）：冗余率 + 膨胀倍数时间序列 + 各模式的消失/复现情况。

## 6. 红线

- 只读：不改被审计文件、不改代码、不新增规则
- 无行号不指控；算术未复核不下「正确」结论
- 不因绝对长度单独定罪，但**必须对照最短充分路径测量膨胀倍数后定罪**；不用「根因」等确定性词下无证据结论
- 建议克制：防规则膨胀
