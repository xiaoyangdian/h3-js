## `[P1]` Skill 路由表（我正要做 X → 加载 Y）

完整触发条件与相邻技能的分界以各 `SKILL.md` 的 `description` 为准，本表只做快速索引。

| 技能 | 一句话触发 |
|---|---|
| `report-change` | 变更交接 / Markdown 留档 / Git message（代码改动结束自动调用） |
| `commit-msg` | 暂存区提交消息快捷入口（report-change 预设；review-change 通过后自动交接） |
| `diagnose-issue` | 故障排查（跑不过 / 不显示 / 不生效 / 数值不对，**第一动作加载**） |
| `review-change` | 只读审查本次变更（改完探针后自检、用户要求 Review） |
| `dev-spec` | 单文件开发规格（`write` 创建 / `run` 执行）；一个切片的规格与任务拆解 |
| `tech-gate` | 技术选型 / 装包 / 改构建 / 引入库（**确认前不得安装**） |
| `openspec-mini` | 规格生命周期：`specs/` 记当前事实、`changes/` 管提案与增量（大切片开工时） |
| `agent-retro` | AI 行为复盘（**仅用户明确点名**） |
| `thinking-audit` | 思维链导出文本冗余审计（用户提供导出文件时） |
| `ui-verify` | 浏览器 Console 几何断言脚本（棋盘/DOM 尺寸、还原度验收） |

### 多技能同时命中时的裁决

- `[P1]` **任务收尾**：代码改动完成同时命中 `ui-verify`（自动）与 `report-change`（自动）时，先 `ui-verify` 生成脚本提示用户验证，验证环节结束后再 `report-change` 交接，不并列输出。
- `[P0]` **排查类请求**（跑不过 / 不显示 / 不生效 / 数值不对 / 报错类）：跳过 `01-clarify` 的完整意图分析流程，第一动作直接加载 `diagnose-issue`；开工复述仍按 `02-redlines`「意图先复述」的排查格式。
- `[P1]` **用户点名优先**：用户明确点名某个 Skill 时按点名执行；未点名且多个 Skill 都可能匹配时，先问一句再加载，不并列展开。
