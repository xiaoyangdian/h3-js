# 技术选型门禁

## 职责

本规则约束项目中尚未确定的技术选择（不限技术栈：Web 前端、移动端、Node.js / 后端服务、工具项目均适用）。代理可以主动询问、比较候选并给出推荐；真正的门禁是：**用户确认前不得把候选方案应用到项目。**

## 已知边界

- 框架、语言与运行时边界（前端框架、后端语言、目标平台等），只有在用户明确确认或当前有效项目文件能够证明时，才视为已选定。本 Skill 不预设任何"默认技术栈"。
- 包管理器、构建工具、UI 组件库、状态管理、路由、请求层、后端框架、数据库 / ORM、测试框架和专项库，只有在用户明确确认或当前有效项目文件能够证明时，才视为已选定。
- **各端 / 各模块 / 各仓库选型互相独立**：一处已确认的方案不自动适用于另一处。跨端 / 跨仓共享物（Design Token、请求封装、工具函数等）必须单独确认后才可共享。
- 参考材料、截图、示例代码和行业惯例可以帮助形成候选，但不能单独构成已经确认的技术决定。

## 可以直接沿用

- 当前有效项目文件已使用某项依赖或工具，且任务只是在既有范围内按原模式修改。
- 用户在当前任务或有效项目规范中明确指定方案。
- 技术细节不新增依赖、不改变公共约定，也不影响后续项目结构。

沿用现状不等于获得升级、替换或扩展该技术的授权。

## 可以主动提供候选

项目为空、存在多种合理方案或用户需要作出技术决定时，代理可以主动：

- 提供少量候选方案。
- 给出推荐方案及其与当前需求的匹配理由。
- 说明开发成本、还原效果、生态、维护和后续接入方面的取舍。
- 把构建工具、组件库、路由、状态管理等组成一个完整候选栈，方便用户整体选择。

提供组合方案时必须：

- 明确列出组合中的每个组成部分。
- 区分必要项和可选项，不因组合推荐就默认所有依赖都必须安装。
- 允许用户自定义、删减或分别选择。
- 将“常见”“生态丰富”等作为参考理由，而不是替代用户确认。

## 必须获得确认后才能实施

以下动作必须在用户明确选定方案后执行：

- 安装、新增、替换或升级依赖。
- 创建或替换脚手架、锁文件和构建配置。
- 引入 UI 库、状态库、路由、请求库、后端框架、ORM、测试工具或专项库。
- 按候选方案创建基础封装、目录结构或公共接口。
- 因技术选型改变部署方式或项目结构。

用户只是查看候选、让代理推荐或尚未提交问题答案时，不视为已经确认。

## 选型问题的表达

询问时可以同时提供多个相关决策，例如页面范围、技术方案和数据来源，只要：

- 每个问题都与开始实施直接相关。
- 候选项明确标记为建议而不是项目事实。
- 用户可以输入自定义答案。
- 用户提交选择前不执行任何候选方案。

## 项目地基联动

本仓库（HeroWO 战斗原型）的地基**已经确认**：零依赖单文件静态页 + 纯 Node 探针，见 `00-project-routing`「技术栈边界」与 `03-battle-domain`。因此这里不存在"待选型"的地基项，不要拿本规则去重开一轮架构选择。

只有下列情况才需要集中梳理地基（届时先问用户是否单独引入 `project-foundation` 技能——本技能集未复制它）：

- 另起子项目 / 新端（例：文字版 UI 之外再做一个移动端壳）。
- 多项相互影响的决定同时未定（构建、语言、包管理器、UI 策略、路由、状态、测试）。
- 用户明确要求设计项目架构或完整候选技术栈。

任何地基候选输出中的 Candidate 都不是已确认选型，不得绕过本规则安装依赖或创建脚手架。

## 事实有效期

- 在同一目标仓库且当前有效项目文件没有冲突变化时，沿用已经确认的方案，不重复询问。
- 新会话仍应读取当前项目事实，不沿用已经失效的旧状态。
- 发现分支、依赖、锁文件或配置变化使旧结论失效时，说明新证据并重新确认。

## 文档与实施

- 未确认方案在技术文档中标记为 `Candidate` 或待确认，不伪装成既定架构。
- 用户确认方案后，可以在已确认需求范围内实施，不需要再次逐依赖询问。

## 本项目现状（HeroWO）

- `[P0]` 当前边界**已经确认并锁定**：原生 HTML + SVG + 单 `<script>` IIFE，零依赖、零构建、无 `package.json`；测试是纯 Node 脚本（只用 `fs` / `path` / 内置模块）。这不是"待选型"，是既定事实。
- 出现下列任何一项时，先按上面的流程走确认，不得直接落地：引入 npm 包、加打包器（Vite / esbuild）、拆模块 / 上框架、把探针改成 Jest / Vitest、引入 CDN 运行时库。
- 候选方案必须回答一个额外问题：**加了它以后 `battle-ui/index.html` 还能不能双击直接打开？** 不能 = 破坏了本项目最基本的使用方式（`02-redlines`「零依赖红线」）。
- 用户确认引入后，仍要满足：探针继续可用、16 套 586 项基线全过、不改变 `__T` 注入面（`03-battle-domain`）。
