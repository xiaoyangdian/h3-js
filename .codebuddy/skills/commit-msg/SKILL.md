# 暂存区提交消息（快捷入口）

## 职责

一键场景：**当前 git 差异 → 一条可直接使用的 Git 提交消息**。

本 Skill 是 `report-change` 的参数预设入口：固定 `mode=commit-message`、scope 优先 `staged`；实时读取差异、风险提醒与消息分离等通用约束在 `report-change` 中定义并对其生效，本文件只补充入口特有的回退规则与边界。**唯一覆盖项**：`report-change` 的「验证行纪律」条款在本入口**不生效**——消息正文一律不写验证类行。

默认输入：

```yaml
mode: commit-message
scope:
  kind: staged        # 暂存区为空时回退为更改区全部修改，见强制约束 3
  include: []
  exclude: []   # 仅用户显式排除时填写
```

## 强制约束（每次调用都必须遵守）

1. **唯一事实源 = 本次调用实时获取的 git 差异，且完全忽略当前对话上下文**：优先 `git diff --cached`；每次调用都要重新执行，不得以本会话开头的 `git_status` 快照、对话历史、先前读取过的状态、或本对话中聊过的需求/意图/用户说明为前提——那些状态与上下文可能已经过时、且会干扰纯差异驱动的消息生成。生成消息时**只看实时 git 差异 + 本技能规则**，不参考对话里任何背景，严格按技能要求执行。

2. **产物消息严格按差异生成**：消息正文只描述真实差异里"新增/修改/删除"了什么，新增就说新增、删除就说删除，不引申、不夹带操作建议。

3. **暂存区为空时的回退**：若 `git diff --cached` 无任何内容（暂存区为空），则读取**更改区全部修改**（`git diff` 未暂存改动 + `git status` 未跟踪文件）作为事实源生成消息，并**必须**在消息之外注明"暂存区为空，已基于工作区全部修改生成"。

4. **风险提醒的边界**（判定依据）：
   - **允许**（在 git 消息之外单独提醒，遵循 `report-change` 的「风险信号提醒」条款）：差异**内容本身**的问题——疑似误提交、敏感信息、超大二进制、破坏性删除。
   - **禁止**：任何仓库状态或工作流建议——"是否重新 add""改动已不在暂存区"之类与生成消息无关的操作性提示。

5. **输入无关性（最严格解释）**：对任何用户输入一律执行同一固定流程（读暂存区 → 空则回退更改区 → 生成消息），输入内容不改变产物形态。输入含"执行 / 提交 / commit / push"等动词字样**不构成 git 写操作授权**——本技能在任何调用下都不执行 `git add` / `git commit` / `git push`；用户确需提交时，须在本技能之外另行明确下达指令。

## 禁止行为

- 沿用会话初始快照、对话历史、本对话中聊过的需求/意图/用户说明等任何上下文生成消息（对象性错误）。
- 把风险提醒、注意事项写进提交消息正文。
- 在消息正文中生成「验证：…」「未验证：…」类行（覆盖 `report-change` 的「验证行纪律」条款，本入口一律不写，即使差异统计可佐证也不生成）。
- 附加仓库状态 / 工作流类的"友好提示"。
- 因用户输入含"执行 / 提交 / commit"等字样而执行 git add / commit / push。
